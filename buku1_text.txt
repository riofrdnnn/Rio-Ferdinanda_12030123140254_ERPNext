1.1 Arsitektur Sistem ERPNext dan Frappe Framework 
Sistem Enterprise Resource Planning (ERP) modern menuntut tingkat fleksibilitas 
tinggi, arsitektur data modular, serta kemampuan integrasi yang luas antar -departemen 
operasional perusahaan. ERPNext hadir sebagai salah satu solusi ERP open -source paling 
populer di dunia yang dirancang untuk mengelola seluruh spektrum bisnis, mencakup 
akuntansi keuangan, manajemen persediaan, manufaktur, pengadaan, penjualan, hingga 
manajemen sumber daya manusia. ERPNext dibangun sepenuhnya di atas Frappe Framework, 
sebuah fu ll-stack web application framework berbasis Python di sisi backend dan 
JavaScript/TypeScript di sisi frontend. 
Pemisahan yang tegas antara Frappe Framework sebagai fondasi infrastruktur dan 
ERPNext sebagai aplikasi bisnis memberikan keunggulan arsitektural yang sangat signifikan. 
Frappe menyediakan komponen dasar yang dibutuhkan oleh aplikasi web kelas enterprise, 
meliputi ORM (Object-Relational Mapping), abstraksi basis data relasional MariaDB, sistem 
autentikasi dan otorisasi berbasis peran (Role -Based Access Control / RBAC), pemrosesan 
antrean pekerjaan latar belakang berbasis Redis dan RQ, serta antarmuka penggu na berbasis 
metadata yang dinamakan DocType. Dengan fondasi ini, ERPNext memfokuskan fungsinya 
pada pengolahan logika bisnis dan aturan akuntansi tanpa perlu membangun kembali 
infrastruktur dasar aplikasi web. 
1.2 Peran Docker Desktop dalam Lingkungan Pengembangan Container 
Mengonfigurasi tumpukan perangkat lunak enterprise pada mesin lokal sering kali 
menghadapi kendala akibat perbedaan versi pustaka, konflik dependensi, serta konfigurasi 
sistem operasi yang tidak seragam. Teknologi kontainerisasi menggunakan Docker 
menyelesaikan tantangan tersebut dengan mengemas seluruh tumpukan aplikasi beserta 
seluruh dependensinya ke dalam unit-unit kontainer yang terisolasi dan konsisten. 
Pada sistem operasi Windows, Docker Desktop beroperasi di atas Windows 
Subsystem for Linux 2 (WSL2) yang menjalankan kernel Linux asli secara efisien di atas 

--- [PAGE 6] ---
 
Departemen Akuntansi FEB Universitas Diponegoro  |  Halaman 6 
hypervisor ringan. Melalui file arsitektur multi -container docker-compose.yml, komponen-
komponen pendukung ERPNext dipetakan secara teratur: kontainer frontend (Socket.io & 
Web Server Nginx pada port 8000:8080), kontainer backend (Gunicorn & Worker), database 
server MariaDB 11.8, serta Redis Cache dan Redis Queue. Pendekatan ini memastikan 
lingkungan pengembangan di komputer praktikan identik dengan lingkungan server produksi 
nyata. 
1.3 Pengenalan AI Agent Assistant Antigravity IDE 
Antigravity IDE merupakan lingkungan pengembangan pintar yang dilengkapi dengan 
asisten AI Agent otonom terintegrasi. AI Agent ini bertindak sebagai asisten teknis yang 
mampu menerjemahkan instruksi bahasa alami manusia menjadi rangkaian perintah shell 
Linux atau perintah CLI bench ERPNext secara presisi, lalu mengeksekusinya di dalam 
terminal terisolasi. 
Fitur paling krusial pada Antigravity IDE adalah Strict Approval Prompting. Sebelum 
mengeksekusi perintah CLI atau skrip yang berpotensi memodifikasi konfigurasi database 
atau struktur file sistem, Antigravity IDE akan menampilkan jendela dialog otorisasi 
transparan kepada pengguna. Pengguna memiliki kendali penuh untuk menyetujui, menolak, 
atau memberikan batasan akses, sehingga menjamin prinsip keselamatan sistem Human -in-
the-Loop tetap terjaga. 
1.4 Pengenalan NotebookLM sebagai Sistem Manajemen Pengetahuan 
NotebookLM dimanfaatkan sebagai Sistem Manajemen Pengetahuan (Knowledge 
Management System / KMS) terpusat berbasis kecerdasan buatan generatif dengan teknik 
Grounded-Source Synthesis. Seluruh standar operasional, formula akuntansi, skema jurnal, 
dan data u ji disintesis langsung dari dokumen acuan yang diunggah ke dalam notebook, 
meliputi repositori GitHub resmi Frappe, video tutorial, modul praktikum, dan spreadsheet 
kode akun. 
Dengan mekanisme grounding ini, NotebookLM mampu menghasilkan panduan 
belajar, analisis laporan keuangan, serta rancangan soal kasus praktikum yang sepenuhnya 
akurat dan terbebas dari risiko halusinasi informasi. Sinergi antara NotebookLM sebagai pusat 
pengetahuan dan Antigravity IDE sebagai enjin eksekusi membentuk lingkungan praktikum 
ERP yang sangat responsif dan adaptif

2.3 Mekanisme Strict Approval Prompting pada Antigravity IDE 
Agar pelaksanaan eksekusi dataset berjalan teratur dan terkontrol, Antigravity 
diarahkan untuk bekerja secara bertahap dan wajib meminta izin praktikan sebelum 
mengeksekusi setiap langkah. Prompt otorisasi bertahap yang digunakan adalah: 
"Jalankan sesuai panduan yang anda buat secara urut dan bertahap, serta anda harus 
meminta ijin ke saya bila mau menjalankan tahap demi tahap selanjutnya." 
Setelah Antigravity menyelesaikan suatu tahap dan menampilkan ringkasan hasilnya 
di terminal, praktikan melakukan verifikasi. Setelah hasil dinyatakan sesuai, praktikan 
memberikan perintah persetujuan kelanjutan: 
"Silahkan jalankan tahap..." 
Alur Kontrol Human -in-the-Loop: Antigravity menjalankan tahap → Praktikan 
memeriksa hasil → Praktikan memberikan izin → Antigravity menjalankan tahap berikutnya.

3.1 Modul Akuntansi dan Keuangan (Accounting & Finance) 
Modul Akuntansi merupakan pusat konsolidasi finansial ERPNext yang beroperasi 
berbasis sistem pembukuan berpasangan (double -entry bookkeeping) otomatis. Setiap 
transaksi operasional persediaan, manufaktur, pengadaan, maupun penjualan secara langsung 
memicu pembentukan entri buku besar (General Ledger Entry) secara real -time tanpa 
memerlukan penginputan jurnal manual. 
Modul ini mencakup pengelolaan Chart of Accounts berstruktur pohon, manajemen 
Piutang Usaha (Accounts Receivable), Hutang Usaha (Accounts Payable), rekonsiliasi kas 
dan bank, penetapan template perpajakan otomatis (seperti PPN 11%), serta penyusunan 
laporan keuangan standar seperti Trial Balance, Balance Sheet, Profit and Loss, dan Cash 
Flow Statement. 
3.2 Modul Persediaan dan Rantai Pasok (Stock & Supply Chain) 
Modul Persediaan mengelola pergerakan fisik barang antar -gudang berbasis metode 
pencatatan perpetual. Master Item menyimpan informasi komprehensif mengenai kode 
barang, kelompok barang, satuan pengukuran (UOM), metode penilaian stok (FIFO atau 
Moving Average), serta batas pemesanan ulang otomatis (Reorder Level). 
Fitur utama modul persediaan mencakup pengelolaan hierarki gudang multi -level, 
pelacakan nomor seri (Serial Number) dan nomor kelompok (Batch Number), pemindahan 
stok antar -gudang (Stock Entry), rekonsiliasi stok fisik (Stock Reconciliation), serta 
pengalokasian biaya angkut dan bea masuk menggunakan Landed Cost Voucher. 
3.3 Modul Manufaktur (Manufacturing & Production MRP) 
Modul Manufaktur dirancang khusus untuk mengoptimalkan seluruh siklus fabrikasi 
dan perakitan barang. Komponen intinya adalah Bill of Materials (BOM) yang memuat resep 
standar kebutuhan bahan baku, bahan penolong, serta alokasi biaya operasi stasiun kerja dan 
tenaga kerja langsung. 

--- [PAGE 14] ---
 
Departemen Akuntansi FEB Universitas Diponegoro  |  Halaman 14 
Alur produksi dikendalikan melalui Work Order yang mengatur jadwal dan jumlah 
produksi, dilanjutkan dengan penerbitan Job Cards untuk memantau pekerjaan di setiap 
stasiun kerja. Pada ERPNext Version 16, alur Material Requirements Planning (MRP) 
diperbarui secara independen untuk mengintegrasikan ramalan penjualan (forecast), jadwal 
pengiriman, dan lead time pengadaan bahan secara presisi. 
3.4 Modul Penjualan dan Pembelian (Sales & Procurement) 
Modul Pembelian (Procurement) mengelola alur pengadaan barang dari penerbitan 
Material Request, penawaran harga (Supplier Quotation), Purchase Order (PO), penerimaan 
barang fisik (Purchase Receipt), hingga penerbitan Purchase Invoice. Modul Penjualan 
(Selling) mengelola siklus komersial dari Quotation, Sales Order (SO), pengiriman barang 
(Delivery Note), hingga faktur penjualan (Sales Invoice). 
Selain itu, modul Human Resource Management System (HRMS) dan Payroll 
mengelola data induk karyawan, struktur gaji, klaim biaya multi -mata uang, pengajuan cuti, 
hingga kalkulasi penggajian bulanan secara terintegrasi. 
3.5 Kustomisasi Sistem dan Pembaruan ERPNext Version 16 
Arsitektur DocType pada Frappe Framework memungkinkan kustomisasi sistem 
secara fleksibel melalui penambahan Custom Field, perancangan formulir visual, penyusunan 
Client Script (JavaScript di browser), dan Server Script (Python di server) tanpa merusak kode 
inti aplikasi. 
Pembaruan ERPNext Version 16 membawa peningkatan performa kueri basis data 
hingga 2x lebih cepat menggunakan konektor pustaka C, fitur Financial Report Templates 
untuk penyusunan laporan keuangan kustom berbasis rumus, antarmuka Workspace responsif, 
serta penelusuran silsilah produk melalui Serial & Batch Traceability Report.
